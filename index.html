Metric definitions and calculation notes

Open each metric to inspect the calculation and its interpretation. Numbers are not standalone fund ratings.

Sharpe ratio

Annualised mean daily scheme return less the daily risk-free assumption, divided by daily standard deviation, then multiplied by √252. Higher is not automatically better across different categories or periods.

Sortino ratio

Annualised mean excess return divided by downside deviation. Downside deviation uses daily returns below the configured target rate. The target assumption must be disclosed.

Alpha and Beta

Beta is covariance of scheme and benchmark daily returns divided by benchmark variance. Alpha is the annualised daily CAPM intercept after the configured risk-free assumption. Results depend on benchmark and sample period.

Information Ratio

For equity-oriented schemes, daily arithmetic excess return divided by the standard deviation of daily arithmetic excess returns, using the Tier 1 benchmark. The SEBI circular does not prescribe a √252 multiplier in this formula. This prototype estimate is not the AMC / AMFI reported IR.

Tracking error and difference

Tracking error is annualised volatility of daily active returns. Tracking difference is scheme performance less benchmark performance over the same matched period. These are central for index funds.

Rolling returns

Each eligible NAV date becomes a start date. The engine finds the first available observation on or after the holding-window target date. Adjacent windows overlap and are not independent observations.

Annualisation uses 252 trading days for volatility, Sharpe, Sortino, Alpha and tracking error. The Information Ratio uses daily arithmetic active returns and an annualised estimate (√252); it is shown only for equity-oriented schemes. Reconcile with AMC / AMFI-reported IR before regulatory comparison. Exact-date TRI matches only, no forward-fill. Sources: SEBI circular ↗ · AMFI IR explainer ↗. Full formulas and caveats are in the repository methodology note.

Methodology. For every eligible NAV date, the engine finds the first available NAV on or after the date shifted by the selected number of calendar months. It computes the holding-period return as end NAV ÷ start NAV − 1. CAGR mode annualises that return over the selected calendar window. Daily, weekly and monthly frequencies change the spacing of start dates, not the return endpoints. Overlapping windows are not independent observations.
Important limitation. This rolling lab currently calculates scheme-only NAV returns until a matched benchmark TRI is imported in Advanced view. We will not compare against a price index or fabricate benchmark observations.
